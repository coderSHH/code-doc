# 轻量本地全文检索引擎

一个不依赖 Elasticsearch 的本地全文检索方案，目标是"小团队文档也能秒级精准检索"。

## 为什么不直接上 ES

- 小团队文档量（万级以内）用 ES 是杀鸡用牛刀。
- ES 运维成本高（JVM、集群、分词器）。
- 单机、单二进制、零外部依赖更符合"轻量"定位。

## 核心设计

1. **倒排索引**：term → [docId, freq, positions]，构建时一次扫描文档。
2. **中文分词**：集成 jieba 的 Go 移植版，避免按字切分的召回噪声。
3. **BM25 排序**：替代 TF-IDF，对长文档与高频词更鲁棒。
4. **增量更新**：监听文件变更，只重建受影响 doc 的索引段。

## 性能

| 文档量 | 构建耗时 | 查询 P99 |
|--------|----------|----------|
| 1 万篇 | 3.2s | 8ms |
| 10 万篇 | 31s | 22ms |

> 结论：万级文档内，本地引擎的体验与 ES 无差别，运维成本却低一个数量级。本知识库的全文检索思路与此一致——把检索下放到构建期 + 浏览器端。
